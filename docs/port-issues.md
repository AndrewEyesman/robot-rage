# Port issues

Issues found while porting the whole game (`port/`), kept as we go. Each says what
happens, why, and what's decided. "Original" means the game's own scripts behave this
way (Adobe's player does the same); "port" means the port differs from the original;
"tooling" is about our own setup.

Status: **open** (needs a decision or work), **kept** (faithful to the original, left
as is on purpose), **fixed**.

## Fixes to the original

Faithful to the original but bad for play, in a browser or anywhere. The maintainer's rule
(2026-10-24): functionality first, then accuracy, so these are fixed without waiting
for a decision, as enhancements kept apart from the translated scripts
(`movies/arena104/enhancements.ts` in the arena, `movies/fixes.ts` elsewhere), each switchable back to the original (`?quirks=...`)
and guarded by a regression check.

## Fixed along the way

Found by comparing with Adobe's player (or dirplayer), fixed in the runtime:

- Only 3 of the spear gun's 5 spears fired (the maintainer; port only). Each shot's spear leaves the gun's child list, so from the fourth shot `child[6 - tamleft]` is past its end; the port's translation read `.worldPosition` of VOID and the shot failed before the ammo count. In Adobe's player `node.child[n]` past the end followed by a property reads the node's own property (measured: `model(2).child[9].worldPosition` is model 2's position), so the original fires all 5 (those shots start at the gun's position; the spear behavior flies the gun's first child). The translation (arena104 s235) now does the same. `weapon-trace spear_front_five` / `spear_back_five` fire all 5 against dirplayer (which also tolerates it).
- `pass` ends the handler (translated as `return pass()`).
- After `go(x)`, `the frame` already reports x; otherwise every `go(label) ... go(the frame)` undid the jump.
- `netTextResult` turns LF / CR LF into CR (measured in Adobe); main.ini parsed wrong without it.
- `symbol()` skips leading whitespace and reads one name (`symbol(LF & "filelist")` is `#filelist`).
- Shape borders are stored one-based (1 = none): the login's newsletter box drew a stray black outline.
- Text members take their box from the score's sprite size; empty text members keep their own default style (the robot list's names in yellow Impact).
- A script error ends only the failing handler, as Director's alertHook does, instead of the whole frame.
- Text layout: per-glyph rounded advances, line height including the line's RETURN, paragraph spacing (dirplayer's parser read the wrong fields), field +1 px lines and clipping, tabs.
- Sprite positions round to the nearest pixel like Adobe (dirplayer truncates; this settles the open question in docs/collision.md).
- Setting a text member's colour stored an rgb() value the renderer couldn't read (the lobby's room list drew black); it stores `#rrggbb` now.
- Garage, measured in Adobe: sprite loc and image coordinates round; locZ survives a span change; a release over another sprite sends mouseUpOutSide to the pressed one and mouseUp to the one under the pointer; Background Transparent text labels with no mouse handlers let clicks through; ink 36 doesn't colourise 8-bit bitmaps; copy-ink text fills with its bgColor; text members' real box size is extracted; new behaviors are created after the endSprites (a frame script's endSprite wiped the buy room's behaviors); `member.image = img` writes into the existing image; image draw/fill follow Adobe's line, outline and brush rules.
- From the unit tests: a script-set property on a sprite without behaviors now lasts its span (the player treats a run of the same member as the span); `sprite.visible` belongs to the channel and outlasts spans; a released puppet takes the score sprite back in full.
- Server: the garage saves the paint map without a session (robot id and name only), which the test server refused with err 18 (the client then logs you out); `setrobotmap` now accepts that (a given session must still own the robot). The 8091 test server needs a restart to pick it up.
- A caret blinked in the robot list's SCRAP ROBOT label (the maintainer): the keyboard focus stayed on the channel after the password field there was replaced by the label. The focus now goes with its sprite (unit test and `login-robot-list` check).
- `rgb("0x...")` parses as hex; `vector * vector` is the dot product.
- After a slow frame (a 3D world being built, textures uploaded) the player ran up to 4 frame cycles per draw to catch up with the clock, so animations skipped ahead. Director plays every frame and a late one just makes the movie slower for a moment; the player now runs at most one frame cycle per draw and starts the next period after a late frame. Traced with `port/tools/motion-trace.mjs` (sprite positions per draw): no more multi-cycle draws. The slide-in jumps the maintainer reported (arena control panel, garage doors) are a different, original bug: doorbehavior closes toward x=0 (see "Fixes to the original").

## Server

The self-hosted server (`server/`) stood in for Shockplay's and trusted the client
completely. For hosting real players (the maintainer, 2026-10-24) it now checks results and money
itself; the client changes that go with it are enhancements like the others.

| 54 | **Ranked results were whatever the winner said.** After each ranked round only the winner reported (`setrobotscore`; the host alone for a tie) and the server updated both robots for any logged-in session, against any robot, match or not; `setrwgames` (the host's match start, no session) was only logged. Now (`server/results.mjs`) the host's `setrwgames` opens a match between the two robots (never two robots of one member), both players report every round, and a round counts (stats, score, prize) only when the two reports agree within 30 s, for an open match (2 h without activity closes it; first to 3 wins, at most 15 rounds). A single report (an old client's winner-only report), disagreeing reports, or reports with no started match record nothing; both reporters get the usual `#err: 0, #score`. **Walkovers and disconnects:** the side that vanishes never reports, so the survivor's report is never confirmed and the round doesn't count, for either side; faking a disconnect wins nothing, it only voids the round in progress (rounds confirmed before it stand). A surrender counts: the surrendering client already reports its opponent as the winner.
